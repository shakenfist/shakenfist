    Phase 1: Relocate the renderer's tests¶

    Master plan: PLAN-bugreport-split.md.

    Planning effort¶

    Medium. The work is mechanical: 651 lines leave one file and arrive in another, unchanged. The judgement was in confirming the destination compiles under every build the renderer has, and in settling the master plan's open questions 1 and 3 before phase 3 acts on them. Both are done below.

    Review effort: low. The commit is a move; the review is a diff of the moved block against the original, which the Definition of done makes a command rather than a reading.

    Scope¶

    In:

    • Move nine snapshot serialisation tests and the one helper they share out of ryll/src/bugreport.rs and into a new shakenfist-spice-renderer/tests/snapshots.rs.
    • Delete the two test-module imports the move strands.
    • Lower ryll/src/bugreport.rs's entry in tools/source-size-baseline.
    • Answer the master plan's open questions 1 and 3, and correct the master plan where this survey found it wrong.

    Out:

    • Every other test in ryll/src/bugreport.rs, including keyboard_snapshot_serialises and test_app_snapshot_serialises, which test ryll's own KeyboardSnapshot and AppSnapshot.
    • Any production code. Nothing in ryll/src/ or shakenfist-spice-renderer/src/ changes in this phase.
    • docs/diagnostics.md's claim that ChannelSnapshots is "the struct in ryll/src/bugreport.rs". It is wrong today, but the re-export it came from survives until phase 3, and the sentence has to be rewritten then anyway. See decision 6.
    • Issues #784 and #548, which touch the code this plan moves. See decision 7.

    What the survey found¶

    The master plan's phase 1 section is accurate on its headline claim -- nine tests, destination shakenfist-spice-renderer/tests/snapshots.rs -- and wrong on one number elsewhere. Details, measured on develop at c7793b9:

    1. The moving set is contiguous and self-contained. Lines 2,507-3,150 of ryll/src/bugreport.rs hold test_display_snapshot_serialises, test_inputs_snapshot_serialises, test_cursor_snapshot_serialises, the helper assert_baseline_channel_fields, test_main_snapshot_serialises, test_playback_snapshot_serialises, test_playback_codec_round_trips, test_usbredir_snapshot_serialises and test_webdav_snapshot_serialises; lines 3,260-3,266 hold test_channel_snapshots_new. 651 lines in two blocks, each block starting at a #[test] attribute rather than at the fn -- test_display_snapshot_serialises carries ten lines of #[test] and #[expect(...)] above its signature, and an extraction anchored on the fn lines silently drops two of the nine tests' attributes. The master plan's "roughly 645" was that mistake; sed -n '2507,3150p;3260,3266p' yields 651 lines, nine #[test] and ten fn. Grepping the two blocks for every ryll type in the module returns nothing: they reference only DisplaySnapshot, InputsSnapshot, InputEventRecord, CursorSnapshot, CursorCacheEntry, MainSnapshot, OutstandingResizeSnapshot, PlaybackSnapshot, PlaybackSessionInfo, PlaybackCodec, UsbredirSnapshot, RedirectedDevice, WebdavSnapshot, StreamSnapshot, DecodeResult and ChannelSnapshots -- all defined in shakenfist-spice-renderer/src/snapshots.rs -- plus H264Offer and the serde_json::json! macro.

    2. The helper moves with them. assert_baseline_channel_fields is called from six of the nine moving tests and from nowhere else in the file.

    3. Everything the moved tests touch is public. Every type above is pub and, per an awk pass over snapshots.rs looking for a lowercase field without pub, so is every field of every one of them. ChannelSnapshots::new and snapshot_json_for are pub. So the tests compile as an integration test, which settles open question 3 in favour of tests/snapshots.rs over folding them into src/snapshots.rs.

    4. Both dependencies the moved tests need are already unconditional dependencies of the renderer crate. serde_json = "1" and shakenfist-spice-protocol = { path = ... } are in [dependencies], not [dev-dependencies], and Cargo makes a package's dependencies available to all of its targets, integration tests included. Nothing is added to any manifest.

    5. snapshots.rs has no cfg(feature) gate anywhere, so UsbredirSnapshot and WebdavSnapshot exist in the slim build too. This matters because tools/check-slim-renderer.sh runs cargo clippy --no-default-features --all-targets -- -D warnings and then once per feature in isolation, and --all-targets compiles integration tests. A new test target that referenced a feature-gated type would fail a lane nothing else in CI covers.

    6. The #[expect(clippy::too_many_lines)] survives the move. shakenfist-spice-renderer/Cargo.toml has [lints] workspace = true, so it inherits too_many_lines = "warn" and clippy.toml's too-many-lines-threshold = 200; test_display_snapshot_serialises is 271 lines, so the expectation stays fulfilled and does not become an unfulfilled_lint_expectations warning under -D warnings.

    7. allow-unwrap-in-tests covers integration tests. The moving block has 18 bare unwrap() calls and the workspace lints unwrap_used = "warn". tests/control_socket.rs already has 13 of them with no file-level allow, and CI is green, so the clippy.toml setting reaches tests/.

    8. Two imports become unused and must go. After the move, the test module's use shakenfist_spice_protocol::link::H264Offer and use shakenfist_spice_renderer::snapshots::OutstandingResizeSnapshot have no remaining user in bugreport.rs (0 references outside the moving blocks). serde_json::json has 18 and crate::notifications::NotificationStore stays. Leaving the two produces an unused-import warning, which -D warnings makes a failure.

    9. Nothing is duplicated at the destination. src/snapshots.rs's single test, bytes_totals_sums_every_channel, exercises ChannelSnapshots::bytes_totals, which no moving test touches.

    10. The master plan says four files where the answer is five. ChannelSnapshots is imported from crate::bugreport by app/connection.rs, app/mod.rs, auto_snapshot.rs, main.rs and rdp.rs. The original count missed app/mod.rs, whose use is wrapped across three lines and so escaped a single-line grep. Corrected in the master plan and in docs/plans/index.md as part of this phase's planning commit; a later step should not redo it.

    Related open issues¶

    Neither is in scope; both are recorded so a later phase does not resolve one by accident while moving code past it.

    • #784, "Record webdav channel traffic in the bug-report ring buffer". This is the issue for the asymmetry documented in TrafficBuffers::buffer_for's doc comment, which phase 3 moves into traffic/mod.rs. The comment and the gap both survive the move unchanged.
    • #548, "DisplaySnapshot is shared by every display channel". A renderer-crate design issue about a type whose tests this phase moves. It is an argument for the move: if #548 is ever fixed, the fixture that has to change is then in the same crate as the type.

    Decisions¶

    1. The tests become an integration test, not a unit test. shakenfist-spice-renderer/tests/snapshots.rs, alongside the four test files already there. Findings 3, 4, 5 and 7 above say it compiles and lints; the alternative, folding them into src/snapshots.rs, would take that file from 1,154 lines to about 1,800 and put it in tools/source-size-baseline -- trading the baseline entry this plan is removing for a new one in another crate. Open question 3 is answered; the master plan is updated to say so.

    2. Three sibling modules, confirmed. Open question 1 is answered by the consumer survey above, in favour of what the master plan proposed. The fallback it described (bugreport/traffic/) is not taken, and the master plan's open question 1 is marked answered rather than left for phase 3 to reopen.

    3. The helper moves and keeps its name. assert_baseline_channel_fields has no caller outside the moving set, so it is not left behind and not duplicated.

    4. The #[expect(clippy::too_many_lines)] and its reason move verbatim. The reason is an argument about why one fully populated fixture is the thing under test and must not be split; it is as true in the new file as the old, and rewriting it would lose the argument.

    5. The move is byte-identical apart from the file header. The new file gets a module doc comment and the use lines it needs; every other line is the original. This is what makes the review a diff rather than a re-read, and it is what the Definition of done checks.

    6. docs/diagnostics.md's wrong sentence is fixed in phase 3, not here. It says ChannelSnapshots is a struct in ryll/src/bugreport.rs. That is wrong today, so fixing it now would be defensible -- but the re-export that caused it survives until phase 3, the sentence has to be rewritten then regardless, and this phase's commit is a pure move whose value is that it contains nothing else. One stale sentence for two phases is the cheaper error.

    7. #784 and #548 stay open and untouched. Phase 1 moves tests; neither issue is about the tests. Recording them here is so that phase 3's mover, reading buffer_for's comment about the missing webdav ring, does not helpfully add one.

    8. The baseline is lowered, not left stale. The ratchet only fails on growth, so a baseline entry of 5,110 against a 4,455-line file passes while being wrong. tools/source-size-ratchet.py --update lowers it; the hook's own header says that is the intended way.
