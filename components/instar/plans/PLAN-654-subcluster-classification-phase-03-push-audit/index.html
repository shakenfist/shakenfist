    PLAN-654 phase 3: the push audit¶

    Parent plan: PLAN-654-subcluster-classification.md

    Prompt¶

    Plan phase 3 of PLAN-654-subcluster-classification.md, the mandatory push audit. Phase 2 landed in d42af1f5 (#810), which completes the plan's substantive work. Phase 1 (d08841e3, #801) replaced the ad hoc readings of host offset zero in the qcow2 chain reader, map, measure and check with one classifier that mirrors qemu's seven subcluster types, and refused what qemu calls an invalid entry. Phase 2 stopped the chain reader treating an external data device as a backing layer, bumped the chain config to version 4 for the flag that marks one, and refused the two data-file entries qemu refuses.

    This phase runs PUSH-AUDIT.md over both. The phase plan is the deliverable; implementation is a separate ask.

    Planning effort¶

    Medium. The audit instrument was repaired by the two push-audit phases before this one, and the survey confirmed it resolves this plan's scope correctly. So unlike differencing phase 18, no step here repairs tooling. The judgement is in Decision 3, which overrides the runbook's models for two dimensions, and in Decision 4, which gives the test dimension a measurement to make rather than a diff to read.

    Review effort: medium, concentrated on Scope and Decision 4.

    Scope¶

    In scope. PUSH-AUDIT.md run over the union of the two merge commits that put this plan's phases on develop, taken from the master plan's Merged column:

    d08841e3  Merge pull request #801  (phase 1, and the master plan itself)
d42af1f5  Merge pull request #810  (phase 2)

    Nothing else is in scope. The master plan and the phase 1 plan were committed inside #801 (9bac3c45 is its first commit), and git log --first-parent origin/develop -- 'docs/plans/PLAN-654*' names only these two merges. This branch's own close-out and planning commits are bookkeeping.

    Triage of every finding, and the record of it in this plan, are in scope.

    Out of scope.

    • Fixing findings. Per the plan-push-audit-phase shared block and PUSH-AUDIT.md's push-audit section, findings land as their own pull request after this one merges. That pull request records this phase's merge commit and marks the plan Complete. If the audit finds nothing, this phase closes itself out instead (step 4).
    • The open issues this plan already handed over: #794, #795, #804, #805, #806, #807 and #808. The audit may add to that list; it does not work it.
    • Items the two pull requests' automated reviews raised and the phases declined in writing. They are recorded in each phase plan's execution notes. An agent re-raising one needs new evidence, not a second opinion.
    • The 23 merged branches still on origin, this plan's two among them. delete_branch_on_merge is on, but branches that merge through the queue stay behind. That holds for the whole repository, not just this plan.

    What the survey found¶

    The scope is two merges, and the tool resolves it¶

    Both Merged cells name merge commits: git rev-list --parents -n1 gives three words for each, and both are ancestors of origin/develop. tools/audit/scope-patch.sh --commits-file over them resolves 21 files and writes 12,474 patch lines. The two merges' --shortstat are 19 files (+5,397/-1,108) and 14 files (+3,239/-294), which overlap in 12.

    Area Files Churn (+/-)
    src/crates/qcow2/src/lib.rs 1 +4,136/-890
    src/vmm/src/main.rs 1 +455/-10
    src/shared/src/lib.rs 1 +416/-17
    src/operations/check, map; src/core/src/serial.rs 3 +89/-65
    tests/ (helpers/qcow2_subclusters.py, test_qcow2_subclusters.py, test_check_formats.py) 3 +1,256/-17
    tools/mutate-differencing.sh 1 +222/-34
    docs/ (6 pages outside plans/), CHANGELOG.md 7
    docs/plans/ (this plan's three files, index.md) 4

    That is about a quarter of differencing phase 18's 54,821 lines. It changes the partition argument (Decision 2) but not the conclusion.

    The instrument needs no repair¶

    Differencing phase 18 gave both wave scripts --range and --commits-file (tools/audit/audit-scope.sh), a printed file count, and an exit 9 for an explicit scope that resolves to nothing. Fuzz-autofix phase 2 fixed the inline-script check's line numbers and truncation. PUSH-AUDIT.md now tells a push-audit phase to pass --commits-file and to build the patch with scope-patch.sh rather than by hand. The survey ran scope-patch.sh and got the 21 files above. Nothing in this plan's scope is a workflow file, so the remaining gap fuzz-autofix recorded, that no shellcheck runs on workflow run: blocks, does not bite here.

    The integration suite reaches the new tests in CI¶

    make test-container-core runs every module except test_convert, test_compare and test_info_malicious (Makefile:740-741), so test_qcow2_subclusters and test_check_formats run on every pull request. tools/mutate-differencing.sh --self-test and --check-patterns run in the ci-tooling job (.github/workflows/functional-tests.yml:200,211). What CI does not show is how many of those tests skip. Phase 2's definition-of-done run skipped 549 of 1,805, and a fixture built at run time by qemu-io can skip when the host's qemu lacks a feature. Decision 4 turns that into a measurement.

    Phase 2 moved the harness phase 1's mutation cases run against¶

    The plan added 23 cases and retired 2, so EXPECTED_CASES went from 105 to 126. Phase 1's 1fd5cedd retargeted qcow2-wide-subcluster-alloc-at-host-zero-unfilled and qcow2-wide-subcluster-lookup-loses-the-bitmap at the new refusal, under new names. Phase 2 moved the crate's ScChain test harness to the device layout the VMM writes: the data device at index 1, the backing image at 2. Phase 1's cases were shown to kill against the old layout, and each phase verified only its own new cases. No run has shown that phase 1's cases still kill on the merged tree. That is the cross-phase effect the shared block's accumulated-diff rule exists to catch, so step 2 runs all 23.

    Corrected at source in this branch's planning commit¶

    Recorded here so a later step does not redo the work, and so step 3c verifies it rather than finding it:

    • Seven open issues this plan filed were missing from the master plan's Future work: #794 and #795 (step 1a), #804 and #805 (phase 1 execution), and #806, #807 and #808 (step 2a). Each was recorded only in a phase plan. The runbook's plan check would have found every one. All seven are now Future work entries.
    • Two consider items from #810's review were noted in the session but recorded nowhere. They now sit in Future work: the data-file refusal names no device (item 2, folded into the #806 entry because #806 is what makes it reachable), and the parent-hint flat VMDK has a crate test but no integration test (item 6).
    • The master plan had no ## Status: line. Every other master plan in docs/plans/ carries one under its title, and the runbook's plan check reads it. The line was added, reading In progress.
    • The three Open questions still read as open. Phase 1 answered all three. Each now carries a one-line answer and points at where phase 1 recorded it.
    • "Bugs fixed during this work" was written in the future tense ("is planned to close"). Both phases have landed, so it now says what they closed: #653, #654 and #800 in phase 1, and #792 and #803 in phase 2.

    Still to settle: one Future work entry with no issue¶

    The entry "check's allocation count on data-file images" records instar check reporting 3/4097 where qemu-img check reports 3/16. Unlike its neighbours, it names no issue. #804 is a different defect: it is about the numerator (L2 tables counted as allocated), while this entry is about the denominator. Step 4 measures it on develop and either files it or records that it no longer holds.

    Decisions¶

    1. Audit the union of the two merges, built once by scope-patch.sh. Wave 1 and the wave 2 mechanical script take --commits-file. The four judgment agents get the materialised scope.patch, restricted to their paths, plus the current state of those files, because a patch shows what changed and not what the tree now says. Step 2 checks the patch against the survey's 21 files and 12,474 lines before any agent reads it.

    2. Partition the judgment agents by dimension, not by phase, as differencing phase 18 did, and for the same reason: two per-phase agents would reproduce the per-phase audit the shared block forbids. At 12,474 lines each dimension can read its whole slice, so there is no further split. The runbook's style-conformance judgment agent is folded into 3a rather than run separately.
