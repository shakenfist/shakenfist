    Phase 3: host-only create, no-op preallocation and monolithicFlat¶

    Phase 3 of PLAN-bat-population.md. Read its Situation and the phase 3 paragraph of "Sequencing rationale" first. This file assumes them, and corrects that paragraph where the survey found it wrong.

    Planning effort: medium, as the master plan sets for this phase. The work is host-only and follows two existing patterns: raw create's open-and-truncate, and convert's monolithicFlat descriptor. The survey's one surprise is a naming divergence in code this phase shares (decision 3).

    Decisions already taken by the operator¶

    Every open question in the master plan was resolved with its recommendation adopted (Michael Still, 2026-10-21). The two this phase carries out:

    • Open question 1: preallocation of vmdk, vpc and vhdx is qemu parity. falloc and full produce exactly the image off would, and metadata is refused without promising future support.
    • Open question 2: create -f vmdk -o subformat=monolithicFlat is written by the host with no guest. It is a sparse extent plus the descriptor convert already writes, and it refuses a backing file as qemu does.

    Neither is revisited here.

    Scope¶

    In:

    • create accepts -o preallocation=falloc|full and --preallocation falloc|full for vmdk, vpc and vhdx. Each produces the off image, and metadata is refused in qemu's terms.
    • measure accepts the same through -o, and refuses metadata through -o and --preallocation alike. Its answers do not change.
    • One host function names a monolithicFlat extent the way qemu does. convert uses it, which fixes #820, and create uses it too.
    • create -f vmdk -o subformat=monolithicFlat (and --subformat monolithicFlat) works on the host. It writes a sparse extent under every preallocation mode plus the descriptor, and refuses a backing file, zeroed_grain=on and a grain size.
    • Tests that use the phase 1 pin as the oracle, and the per-phase documentation: docs/create.md, docs/measure.md, docs/convert.md, docs/format-coverage.md and docs/quirks.md.

    Out:

    • VHDX subformat=fixed. It is refused exactly as today, so subformat=fixed,preallocation=falloc still fails on the fixed refusal. Phase 7 lifts it.
    • Cross-version CREATE_CASES baselines for the new cases. They go to phase 10, with the fixed VHDX cases phase 2 moved there (decision 5).
    • qemu's DDB lines in VMDK descriptors. Neither instar VMDK writer emits them today. They are recorded in Future work (decision 4).
    • Any guest, crate or call-table change. Nothing under src/operations/ or src/crates/ changes, and nor does the CreateConfig or MeasureConfig layout.

    What the survey found¶

    Line numbers are against develop at 5c5bba75. The Situation's line numbers for src/vmm/src/main.rs have drifted by about 30 lines since it was written. Its claims still hold, so it is left as it is, and the numbers below are the current ones.

    The refusals are where the Situation says¶

    • create -o parser: parse_create_o_options (main.rs:15276). Its ("vmdk" | "vpc" | "vhdx", "preallocation") arm (:15487-15505) accepts off and refuses the other three modes with "is not yet supported ... (preallocation is implemented for raw and qcow2 only)". The vmdk subformat arm (:15418-15430) already accepts monolithicFlat. zeroed_grain, adapter_type, hwversion and toolsversion are accept-ignored and not stored (:15434-15440).
    • validate_create_args (:19422) refuses monolithicFlat (:19498-19503, "multi-file subformats are not implemented; use instar convert -O vmdk for now"). It also refuses non-off preallocation for the three formats a second time (:19533-19553). A unit test pins the old message (:20012), and so does an integration test (tests/test_create.py:1600-1606).
    • run_create (:18223) applies -o overrides, validates, and sends raw to run_create_raw (:19125) and everything else to the guest (run_create_nonraw, :18331).

    The guest already ignores preallocation for these formats¶

    run_create_nonraw turns args.preallocation into CREATE_CONFIG_PREALLOC_* flag bits for every format (:18354-18359). The create guest reads them only for qcow2 (src/operations/create/src/main.rs:399-404 and :1089), and the host post-pass is qcow2-only (main.rs:18566-18567). Accepting falloc and full would therefore produce the off image unchanged. The host still sends PREALLOC_OFF for these formats (decision 1), so that this stays true however the guest changes.

    measure is half there already¶

    measure --preallocation is accepted for vpc, vmdk and vhdx, and has no effect. --preallocation metadata is accepted too; measured with a build of da9f043f, measure -O vpc --size 64M --preallocation metadata prints the same answer as off. -o preallocation=... is refused as an unrecognised key for all three (parse_o_options, :15018; the catch-all is at :15186). The two spellings disagree. qemu-img cannot measure any of the three formats, so instar's own writer is the only oracle.

    convert names the flat extent differently from qemu (#820)¶

    convert derives the extent as <file_stem>-flat.vmdk (main.rs:14297-14309). qemu splits the basename at its last . and writes <prefix>-flat<postfix>: see filename_decompose, and the "%s-flat%s" format in vmdk_co_do_create (block/vmdk.c:2279-2316 and :2599 in qemu 7.0.0). Measured with qemu-img 10.0.13 and the da9f043f build:

    Output qemu-img extent instar convert extent
    out.vmdk out-flat.vmdk out-flat.vmdk
    out.img out-flat.img out-flat.vmdk
    out out-flat out-flat.vmdk
    .hid -flat.hid .hid-flat.vmdk

    Filed as #820. The image is valid either way, because the descriptor names the extent that was written. The two differ only when the output name does not end in .vmdk.

    qemu also searches for \ and then : when the name has no /. Nothing on a Linux host uses that, and on a:b.vmdk it would put the extent in the working directory while the descriptor resolves it next to itself, so instar does not copy it (decision 3).

    What qemu does around monolithicFlat create¶

    These were measured with qemu-img 10.0.13, and the pin covers all 80 builds where it says so.

    • The extent is sparse, with ftruncate to the virtual size under off, falloc and full. Its length is the size rounded up to 512: a 1000 request gives a 1024-byte extent and RW 2 FLAT. The pin's prealloc-vmdk-monolithicFlat and vmdk-flat-64M cases cover this.
    • With -b, qemu fails: "Flat image can't have backing file" (block/vmdk.c:2429; pin vmdk-flat-backing, all 80 builds).
    • With zeroed_grain=on, qemu fails: "Flat image can't enable zeroed grain" (:2434), and leaves no file.
    • With preallocation=metadata, qemu fails: "Unsupported preallocation mode: metadata", and leaves a zero-byte descriptor.
    • The descriptor carries ddb.virtualHWVersion, ddb.geometry.* and ddb.adapterType, and from 6.2.0 also ddb.toolsVersion. The pin has two groups at exactly that boundary. adapter_type and hwversion change those lines. instar's build_flat_descriptor (src/crates/vmdk/src/lib.rs:261) writes none of them and a constant CID=fffffffe. Its sparse writer omits the DDB lines too, so this is not specific to flat output.

    The pin is a ready oracle, but not for absolute lengths¶

    The phase 1 pin (tests/golden/qemu-create-pins.json) holds seven preallocation cases and two monolithicFlat cases, one group each across all 80 builds except vmdk-flat-64M. qemu_pins.run_case runs <binary> create -f FMT -o ... IMAGE SIZE, which is also instar's command line, so the same runner can measure instar. Its file_length fields cannot be compared directly, though. instar's 64M images are 11264 bytes (vmdk), 4194304 (vhdx; its default block size is #645) and 67109376 (fixed vpc; qemu rounds to CHS) against qemu's 65536, 8388608 and 67125760. Only dynamic vpc agrees, at 2560. What transfers is the pin's shape: every mode's rc, same_bytes_as_off and same_allocation_as_off. Decision 5 builds the tests on that.

    Master plan corrections made in this commit¶

    • The phase 3 paragraph of "Sequencing rationale" said the phase's tests were cross-version info baselines. It now says the pin is the oracle, that the baselines join phase 10's, and that the phase fixes #820.
    • The phase 10 paragraph now lists the monolithicFlat create cases among the CREATE_CASES it adds.
    • Future work gains the VMDK descriptor DDB lines.
    • The Execution table and the docs/plans/index.md row link this file.

    Decisions¶

    1. The host normalises preallocation for vmdk, vpc and vhdx. Once validated, falloc and full are recorded as they were typed in args.preallocation. For these three formats, run_create_nonraw sends CREATE_CONFIG_PREALLOC_OFF. The guest ignores the bits for these formats today, but the parity claim should not rest on that: a future guest reading the bit for vhdx would otherwise change every falloc image silently. No guest change is needed.

    2. One refusal text for metadata, shared by create and measure. It reads <op>: preallocation=metadata is not supported for <format>, built by one helper both validators call. It drops "not yet" and "future work", because qemu refuses it at every version and the plan does not intend to add it. The create -o parser and validate_create_args both use it, as the old text did. For measure, the check sits in run_measure after -o has been applied (:15805-15860), so --preallocation and -o cannot disagree again. Making measure's --preallocation metadata an error for these formats is a deliberate tightening. qemu has no measure answer for them, and measure is defined as a prediction of instar's own writer, which will refuse the mode.

    3. The extent name follows qemu's rule, in one function, and convert changes with it. Add a host function, for example vmdk_flat_extent_path(output: &Path) -> (PathBuf, String), returning the extent path and the name the descriptor records. It takes the basename after the last /, splits it at its last ., and returns <prefix>-flat<postfix> in the output's directory. This covers a leading dot (.hid gives -flat.hid) and no dot at all (out gives out-flat). It does not split on \ or : (survey). Both convert and create call it.

    This changes convert's output for any name not ending in .vmdk. That is the decision a reviewer is most likely to question, because it alters an existing command's behaviour inside a phase about create. Three things justify it:

    • The alternative is two naming rules, or giving create the wrong rule on purpose.
    • The change only moves instar to the name qemu-img writes.
    • The image stays readable, because a descriptor always names its own extent.

    The commit and the PR say "Fixes #820", and docs/convert.md states the rule.

    1. The descriptor stays as convert writes it, without DDB lines and with a constant CID. Matching qemu would mean honouring adapter_type, hwversion and toolsversion (all accept-ignored), computing qemu's geometry, and picking one side of the 6.2.0 toolsVersion boundary. The same work would be owed to the sparse writer. Neither qemu-img info nor any reader instar or qemu ships uses those lines, so the work buys only byte-level fidelity. It goes to Future work. docs/quirks.md records the omission, and #566 already covers the constant CID.

    adapter_type, hwversion and toolsversion stay accept-ignored for monolithicFlat. Three options are refused rather than ignored: * -o zeroed_grain=on, as qemu refuses it. The parser stores the value instead of dropping it. * A grain size, through --grain-size or -o grain_size. Its default is the 0 sentinel; anything else has no meaning for a flat extent. * -b, with instar's wording of qemu's refusal.

    1. The tests take the pin as oracle for shape, and instar's own off image for lengths. New tests in tests/test_create.py run qemu_pins.run_case(<instar binary>, case, workdir) on these cases:
    2. prealloc-vpc, prealloc-vmdk and prealloc-vhdx;
    3. prealloc-vpc-fixed;
    4. prealloc-vmdk-monolithicFlat, once step 3c lands;
    5. vmdk-flat-64M and vmdk-flat-backing, after 3c as well.

    For each preallocation case and mode, rc, same_bytes_as_off and same_allocation_as_off must equal the pin's qemu_pins.expected(case). file_length must equal that of instar's own off image in the same run, and metadata's stderr must be decision 2's text. For vmdk-flat-64M: * extent_length must equal the pin's; * the normalised descriptor must equal the pin's newest group with every ddb. line removed (decision 4); * CID is already normalised by normalise_descriptor.

    prealloc-vhdx-fixed goes in a known-refusal table with the subformat=fixed message. The table must fail with "remove this entry" once phase 7 lets the case pass, the pattern tests/test_vhdx_fixed_fixtures.py uses. Live comparisons against the host qemu-img cover what the pin cannot, and skip when qemu-img is absent: * the four extent-name shapes, through both create and convert; * qemu-img info --output=json of an instar flat image against qemu's own, ignoring filename, cid, actual-size, and the filename and actual-size inside children.

    The cross-version CREATE_CASES baselines stay in phase 10. Adding a case to the instar mirror without its generated baselines fails test_create_cases_match_baselines. Generating them is the 80-version testdata procedure phase 10 owns, and phase 2 already moved the fixed VHDX cases there for the same reason.

    1. monolithicFlat create cleans up after itself, and stays sparse. The steps, in order:
    2. Validate everything first: size, backing, preallocation, zeroed_grain and grain size.
    3. Open the extent with create(true).truncate(true) and mode 0644, as run_create_raw does, and set_len it to the size rounded up to 512. Do not call create_raw_finalize: its falloc and full really allocate, and qemu's extent stays sparse under every mode.
    4. Write the descriptor with build_flat_descriptor, sized from the same rounded value, and sync both files.

    On any failure after a file is opened, remove both files. That includes a descriptor too long for its buffer (the function returns the length it needed, so check it), and it matches what every other instar create does on failure. qemu leaves a zero-byte descriptor on some failures; instar does not copy that. The success line and JSON report the descriptor as filename and the descriptor's length as both metadata_bytes_written and file_size_after, with resolved_unit_size 0.

    Risks and mitigations¶

    • A no-op preallocation hides a guest that starts honouring the bit. Decision 1 sends OFF, and the tests compare every mode's bytes and allocation with off. The management session confirms that a mutant sending the user's mode instead is caught. It is caught only if the guest reacts to the bit, so that mutant is expected to survive, and its survival is the reason for decision 1, not a gap.
    • The convert rename breaks a caller expecting -flat.vmdk. Only non-.vmdk names change. The management session greps tests/, scripts/ and tools/ for -flat.vmdk built from a non-.vmdk output before committing 3b. The phase 3 survey found only .vmdk outputs (tests/test_convert.py:2480-2550).
    • Cleanup removes a file the user cared about. Both files are opened with truncate, as qemu opens them, so a failure after opening has already destroyed the old contents. Removing them is no worse, and a validation failure removes nothing because validation runs first. The management session reads 3c's diff for any removal reachable before the first open.
    • The pin comparison passes vacuously. If run_case raised, or expected returned nothing for a case, a loose test could pass. The mutation scripts break the no-op (allocate under full), the refusal text, the naming rule and the cleanup, and each must be killed.
